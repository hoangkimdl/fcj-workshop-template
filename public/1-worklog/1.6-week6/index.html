Week 6 Worklog

Week 6 Objectives:

  • Learn about Amazon Simple Storage Service (Amazon S3), its role as an object storage service in AWS Cloud, and important concepts such as Buckets, Objects, Storage Classes, and Access Control.
  • Understand how to create and configure Amazon S3 Buckets, manage stored objects, and practice uploading data from a personal computer to S3.
  • Practice deploying Static Website Hosting directly on Amazon S3, configuring public access permissions for website files, and verifying website accessibility through the Website Endpoint.
  • Learn about Amazon CloudFront and practice integrating CloudFront with S3 to distribute website content, improve access speed, and enhance the security of stored data.
  • Learn and practice Amazon S3 Bucket Versioning to retain multiple versions of objects, track changes, and restore data when necessary.
  • Practice moving objects between S3 Buckets using the Move Objects feature and learn about Amazon S3 Cross-Region Replication (CRR) to automatically replicate data across different AWS Regions.
  • Learn security, performance optimization, and cost management best practices when using Amazon S3, including Block Public Access, Bucket Policies, Encryption, Lifecycle Policies, and CloudFront Origin Access Control (OAC).
  • Understand the procedures for checking, cleaning up, and deleting Amazon S3 and CloudFront resources after completing the Workshop to minimize unnecessary costs.

Monday Learn About Amazon S3 and Practice Creating a Bucket and Uploading Data to S3

- Learn about Amazon Simple Storage Service (Amazon S3), a scalable object storage service that provides high availability, durability, security, and performance on AWS Cloud.

- Distinguish between the two basic components of Amazon S3:
  + S3 Bucket: A top-level container used to store and organize data objects. Each Bucket has a globally unique name and is created in a specific AWS Region.
  + S3 Object: The actual data object stored inside a Bucket, including its data content and related Metadata.

- Learn about Amazon S3 Storage Classes, including S3 Standard, S3 Intelligent-Tiering, S3 Standard-IA, S3 Glacier, and S3 Glacier Deep Archive; distinguish the purposes of each storage class based on data access frequency and storage requirements.

Tuesday Practice Deploying Static Website Hosting on Amazon S3 and Configuring Public Access Permissions

- Learn about Static Website Hosting on Amazon S3, which allows static content such as HTML, CSS, JavaScript, and images to be stored and distributed directly without deploying a separate web server.
- Learn about the benefits of Static Website Hosting, including cost savings, automatic scalability, high reliability, and reduced server management requirements.
- Practice accessing the S3 Bucket, opening the Properties tab, and locating the Static website hosting section.
- Enable Static Website Hosting by selecting Enable, choosing the Host a static website option, and configuring index.html as the default document and error.html as the optional error document.
- Save the configuration and check the Website Endpoint generated by Amazon S3 after enabling static website hosting.
- Learn the differences between the Website Endpoint and the S3 Bucket Endpoint, and understand that the Website Endpoint uses HTTP and requires CloudFront to distribute the website over HTTPS.
- Learn about Amazon S3 Block Public Access and its role in preventing unintended public access to Buckets and Objects.
- Practice accessing the Permissions tab, opening Block public access, and unchecking Block all public access as required for the Static Website Hosting exercise.
- Confirm the change by entering confirm in the confirmation dialog and saving the public access configuration.
- Learn about S3 access control levels, including Bucket-level permissions and Object-level permissions; distinguish the roles of ACLs, Bucket Policies, and IAM Policies.
- Practice changing Object Ownership from Bucket owner enforced to Bucket owner preferred and enabling ACLs to support object-level access configuration.
- In the Object Ownership section, select ACLs enabled, confirm I acknowledge that ACLs will be restored, and save the configuration according to the Workshop instructions.
- Access the Objects tab, select website files that need to be publicly accessible, including HTML, CSS, JavaScript, and images, then select Actions → Make public using ACL to grant public read access to the selected Objects.
- Check the access permissions of the Objects after configuration and verify that the website files can be downloaded by Internet users.
- Access Properties → Static website hosting, copy the Bucket Website Endpoint, and open it in a browser to verify the sample website interface.
- Use the browser Developer Tools, open the Network tab, and reload the page to observe the website loading time through the S3 Website Endpoint before integrating CloudFront.

Thursday Learn and Practice Amazon S3 Bucket Versioning and Move Objects Between Buckets

- Learn about Amazon S3 Bucket Versioning, a feature that allows multiple versions of the same object to be retained in a Bucket to prevent data loss caused by accidental overwrites or deletions.
- Learn about the benefits of Versioning, including data protection, change history tracking, previous version recovery, data retention requirements, and collaboration support.
- Understand how Versioning works, in which each Object version is assigned a unique Version ID; uploading a new version does not permanently overwrite the previous version.
- Distinguish between the three Bucket Versioning states: Unversioned, Versioning-enabled, and Versioning-suspended; understand how new versions are created and how previous versions are retained in each state.
- Practice accessing the S3 Bucket, opening Properties → Bucket Versioning, and selecting Edit to enable Versioning.
- Open the index.html file in the source code directory downloaded to the personal computer, use Notepad to edit the content inside the body tag according to the Workshop instructions, and change the text from AWS First Cloud AI Journey to HỌC CLOUD AI VUI BIẾT BAO <3.
- Save the changes using Ctrl + S and upload the modified index.html file to the S3 Bucket using the Upload function.
- Search for index.html, enable the Show versions option to inspect the versions of the same Object, and verify that S3 has retained two versions with different modification timestamps.
- Learn how Versioning affects storage capacity and AWS costs, recognizing that each stored version occupies storage space and may generate additional charges.
- Learn about the role of Lifecycle Policies in automatically managing previous versions and explore the use of MFA Delete to strengthen data protection.
- Learn about the Move Objects feature in Amazon S3, which allows objects to be moved to a different folder (Prefix) within the same Bucket or to another Bucket.
- Practice creating a new S3 Bucket using the pattern aws-first-cloud-ai-journey-xxxx-move, keeping the default settings according to the Workshop instructions, and completing the destination Bucket creation process.
- Access the source Bucket, select all Objects, and use Actions → Calculate total size to check the total number and storage size of the data before moving it.
- Practice selecting Actions → Move, choosing General purpose bucket as the destination type, opening Browse S3, and selecting the newly created destination Bucket.
- Keep the Copy source settings options in the Additional copy settings section unchanged, then perform the Move operation to start transferring the data.
- Monitor the moving process, close the notification after completion, and access the destination Bucket to check its list of Objects.
- Use Calculate total size in the destination Bucket to compare the number of Objects and total storage size after the move, confirming that the objects have been transferred successfully.
- Understand the benefits of moving Objects when organizing, classifying, and managing data across different S3 Buckets.		 05/11/2026 05/11/2026 Start With Amazon S3

Friday Practice Amazon S3 Cross-Region Replication and Review and Clean Up Resources After the Workshop

- Learn about Amazon S3 Cross-Region Replication (CRR), a feature that automatically replicates Objects between S3 Buckets located in different AWS Regions.
- Learn about the benefits of CRR in improving data redundancy, supporting Disaster Recovery, meeting compliance requirements, distributing data geographically, and maintaining system continuity.
- Understand the asynchronous data replication mechanism, in which Objects are automatically replicated to the destination Bucket; the Workshop indicates that replication may generally complete within approximately 15 minutes, depending on actual conditions.
- Learn about the prerequisites for configuring CRR, including enabling Bucket Versioning on both the Source Bucket and Destination Bucket, creating a Replication Rule, and using an IAM Role to grant replication permissions.
- Learn about the factors to consider when selecting a destination AWS Region for replication, including compliance requirements, latency, storage costs, data transfer costs, service availability, and disaster recovery capabilities.
- Practice creating a new Destination Bucket using the pattern aws-first-cloud-ai-journey-xxxx-cross in the N. Virginia Region (us-east-1), while the Source Bucket is located in Singapore (ap-southeast-1).
- Select the previously created Source Bucket and upload the website data to it again according to the Workshop instructions because the Objects were moved to another Bucket in the previous Move Objects exercise.
- Access Management → Replication rules in the Source Bucket and select Create replication rule to configure a new data replication rule.
- Name the Replication Rule PrimaryToSecondary, set its status to Enabled, and select Apply to all objects in the bucket to apply the rule to all Objects within the Bucket’s scope.
- In the Destination section, select Choose a bucket in this account to replicate data to another Bucket within the same AWS Account.
- Use Browse S3 to select the Destination Bucket with the -cross suffix in the N. Virginia Region (us-east-1).
- Enable Bucket Versioning for the Destination Bucket as required by CRR.
- In the IAM Role section, select Create new role so that AWS can create an IAM Role and grant the required permissions for the replication process.
- Keep the remaining settings at their default values, save the Replication Rule, and select No, do not replicate existing objects to prevent previously existing Objects from being replicated.
- Access the Destination Bucket in the N. Virginia Region and check its initial list of Objects before uploading new data to the Source Bucket.
- Practice uploading a new image file from the images directory to the Source Bucket using the Upload function to test the Replication Rule.
- Revisit the Destination Bucket, refresh the page, and verify the appearance of the newly uploaded image after the replication process is completed.
- Learn and summarize Amazon S3 security best practices in the Notes & Best Practices section, including:
  + Keep Block Public Access enabled in Production environments.
  + Prioritize using CloudFront with Origin Access Control (OAC) instead of exposing S3 Buckets directly to the public.
  + Use Bucket Policies to control access permissions in detail.
  + Enable default encryption using SSE-S3 or SSE-KMS, selecting the appropriate encryption method based on data sensitivity.
- Learn performance optimization practices, including configuring CloudFront Cache Behaviors, TTL, Compression, HTTP/2, IPv6, S3 Transfer Acceleration, and Multipart Upload for files larger than 100 MB.
- Learn cost optimization methods, including using S3 Intelligent-Tiering, Lifecycle Policies, S3 Storage Lens, managing previous object versions, and monitoring data transfer costs.
- Learn common errors when using Amazon S3 and CloudFront, particularly 403 Forbidden errors caused by incorrect Block Public Access settings, Bucket Policies, or CloudFront access permissions.
- Distinguish between S3 Website Endpoint and S3 Bucket Endpoint, understanding their differences in Static Website Hosting, HTTPS, OAC, and OAI support.
- Learn about Cross-Origin Resource Sharing (CORS), understand why browsers block requests between different origins, and explore how to configure CORS according to access requirements.
- Practice cleaning up resources after the Workshop by accessing Amazon S3, selecting the relevant Buckets, using Empty to delete all Objects, and then selecting Delete bucket.
- Practice cleaning up CloudFront Distributions by accessing Amazon CloudFront, selecting the created Distribution, choosing Disable, and waiting for the disabling process to complete before selecting Delete.
- Review the S3 Bucket and CloudFront Distribution lists after cleanup to ensure that unused test resources have been removed and unnecessary costs are minimized.		 06/11/2026 06/11/2026 Start With Amazon S3

Week 6 Achievements:

  • Gained an overall understanding of Amazon Simple Storage Service (Amazon S3), including its role as an object storage service in AWS Cloud and its benefits in terms of scalability, availability, durability, security, and cost efficiency.

  • Understood the storage structure of Amazon S3 and distinguished between its two fundamental components:

  • Learned about Amazon S3 Storage Classes and their respective purposes:

    • S3 Standard: Suitable for frequently accessed data.
    • S3 Intelligent-Tiering: Automatically optimizes storage classes based on data access patterns.

    • S3 Glacier: Suitable for long-term data storage, with retrieval times depending on the selected retrieval configuration.
