Week 7 Worklog

Week 7 Objectives:

  • Learn about Amazon Relational Database Service (Amazon RDS), its role as a managed relational database service on AWS Cloud, and its benefits, including automated backups, software updates, resource scaling, and improved availability.
  • Learn about the database engines supported by Amazon RDS, including Amazon Aurora, MySQL, MariaDB, Oracle, Microsoft SQL Server, and PostgreSQL.
  • Understand the essential components and features of Amazon RDS, such as DB Instances, DB Endpoints, DB Subnet Groups, Storage Options, Automated Backups, Manual Snapshots, Multi-AZ, and Read Replicas.
  • Learn about database security mechanisms through Amazon VPC, Security Groups, IAM Policies, AWS KMS, and SSL/TLS Encryption.
  • Practice building a network environment for Amazon RDS deployment by creating a VPC and configuring Public Subnets, Private Subnets, Security Groups, and DB Subnet Groups to control connectivity between the application server and the database.
  • Practice launching an Amazon RDS Database Instance using MySQL, configuring database server specifications, storage capacity, credentials, Multi-AZ deployment options, and secure connectivity settings.
  • Practice launching an Amazon EC2 Instance using Amazon Linux 2023, configuring Key Pairs and Security Groups, and connecting to the server through SSH using MobaXterm.
  • Practice connecting from EC2 to Amazon RDS MySQL through the DB Endpoint and MySQL Command Line Client, using SQL commands to create databases and tables, insert records, and retrieve information.
  • Practice deploying the AWS User Management application using Node.js on EC2, configuring the connection to Amazon RDS through the .env file, and using PM2 to manage application processes.
  • Learn and practice Automated Backups, Database Snapshot management, and database restoration on Amazon RDS to protect data and support Disaster Recovery.
  • Understand the procedures for checking, cleaning up, and deleting Amazon RDS, EC2, DB Subnet Group, and VPC resources after completing the Workshop to minimize unnecessary costs.

- Learn about Amazon Relational Database Service (Amazon RDS), a managed relational database service provided by AWS that allows users to deploy and operate databases on AWS Cloud.
- Understand the role of Amazon RDS in storing and processing structured data, particularly for applications that use relational database management systems and Online Transaction Processing (OLTP).
- Learn about the benefits of Amazon RDS, including automated backups, database software updates, patch management during Maintenance Windows, resource scaling, and high availability support.
- Learn about the database engines supported by Amazon RDS, including:

  + MySQL.
  + MariaDB.
  + Oracle.
  + Microsoft SQL Server.
  + PostgreSQL.

- Learn about Amazon RDS storage options:
  + General Purpose SSD (gp3/gp2): Provides cost-effective storage suitable for various database workloads.
  + Provisioned IOPS SSD (io1/io2): Suitable for systems with high read and write performance requirements.
  + Magnetic Storage: A legacy storage option with limited performance that is not recommended for new deployments.

- Learn about Amazon RDS security mechanisms, such as data encryption at rest using AWS KMS, data encryption in transit using SSL/TLS, network isolation through VPC, and access control using IAM Policies.
- Learn about Amazon RDS scalability options, including storage capacity expansion and compute resource modification based on workload requirements.
- Learn about Automated Backups, which support Point-in-Time Recovery with a retention period of up to 35 days, and Manual DB Snapshots, which are retained until manually deleted.

Tuesday Practice Configuring Security Groups, DB Subnet Groups, and Launching an Amazon RDS Database Instance

- Learn about Security Groups and their role as Virtual Firewalls for controlling Inbound and Outbound traffic for EC2 Instances and RDS Database Instances.
- Access the EC2 Console, open Security Groups, and select Create security group to create a dedicated Security Group for EC2.
- Set the Security Group name to ec2-sg, provide the description Security group for EC2 instances connecting to RDS, and select the previously created VPC.
- Configure the Inbound Rules for ec2-sg, including:
  + SSH (22): Allow access only from My IP for Linux server administration.
  + HTTP (80): Allow access from Anywhere-IPv4 to support Web traffic.
  + HTTPS (443): Allow access from Anywhere-IPv4 to support secure Web connections.
  + Custom TCP (5000): Allow access from Anywhere-IPv4 to test the Node.js application.
- Review the Inbound Rules and complete the creation of the ec2-sg Security Group.
- Create a separate Security Group for Amazon RDS named rds-sg, provide the description Security group for RDS MySQL database instances, and select the same VPC.
- Configure the MySQL/Aurora (3306) Inbound Rule and select the ec2-sg Security Group as the source instead of allowing access from the entire Internet.
- Understand the benefits of using a Security Group as the source, ensuring that only EC2 Instances with the appropriate Security Group can connect to the database.
- Learn the principle of separating Security Groups between application servers and database servers to strengthen resource isolation and access control.
- Access Amazon RDS, select Subnet groups → Create DB Subnet Group to create a group of Subnets for database deployment.
- Set the DB Subnet Group name to rds-subnet-group, provide the description Subnet group for RDS instances, and select the previously created VPC.
- In the Add subnets section, select Subnets belonging to at least two different Availability Zones, preferably Private Subnets for RDS deployment.
- Complete the DB Subnet Group creation process and verify the associated Subnets to ensure that the configuration meets Multi-AZ deployment requirements.
- Access Amazon RDS, select Databases → Create database, and choose the Full configuration method instead of Easy create to customize database settings.
- Select MySQL as the Database Engine according to the Workshop instructions.
- Select the Production template and choose Multi-AZ DB instance deployment (2 instances) to explore high-availability database deployment.
- Set the DB Instance Identifier to db-instance, the Master Username to admin, and select Self managed under Credential Management.
- Configure a strong administrative password according to the Workshop requirements, confirm the password, and store the credentials securely for subsequent connection steps.
- Configure the Instance Class as db.m5.large, the Storage Type as General Purpose SSD (gp3), and the Allocated Storage as 20 GiB according to the Workshop instructions.
- In the Connectivity section, select Don’t connect to an EC2 compute resource, use the previously created VPC, and select the rds-subnet-group DB Subnet Group.
- Set Public Access to No to prevent the database from being publicly accessible over the Internet.
- In the VPC Security Group section, select Choose existing and attach the rds-sg Security Group to the DB Instance.
- In Additional Configuration, set the Initial Database Name to fcaj, keep the remaining options at their default values, and complete the database creation process.
- Check the RDS Database Instance creation status and verify that the Database Instance becomes available after initialization is complete.
- Access Connectivity & security and select Endpoints to identify the DB Endpoint and Port used by applications to connect to the database.
- Learn how to view Logs & events to monitor database lifecycle events, operational information, and related logs.
- Access Maintenance & backups to explore maintenance schedules, pending software updates, and database backup information.		 17/11/2026 17/11/2026 Get Started with Amazon RDS

- Use the SELECT * FROM user; statement to retrieve and verify all data stored in the table.
- Explore additional SQL commands for database management and inspection:
  + USE database_name;: Switch to the specified database.

Friday Learn and Practice Amazon RDS Backup and Restore and Clean Up Resources After the Workshop

- Learn about the Backup and Restore functionality of Amazon RDS, which helps protect data, recover databases, and maintain system continuity in the event of failures.
- Distinguish between Automated Backups and Manual DB Snapshots:
  + Automated Backups: Automatically managed backups provided by Amazon RDS that support database recovery to a specific point in time within the configured retention period.
  + Manual DB Snapshots: Backups manually created by users and retained until they are explicitly deleted.
- Learn about the Point-in-Time Recovery mechanism of Automated Backups and its ability to restore data to an appropriate point within the retention period.
- Access the AWS RDS Console, select Databases, and open the previously created DB Instance.
- Access the Maintenance & backups tab to inspect backup status, retention periods, the latest recovery point, and other information related to database maintenance.
- Learn how to view Database Snapshots in the Snapshots section and understand their role in protecting database data.
- Practice selecting a DB Snapshot for recovery and using the Restore function to create a new Database Instance from the selected Snapshot.
- Set the DB Instance Identifier of the restored database to fcaj-2 according to the Workshop instructions.
- Review and configure the settings of the new Database Instance, including compute resources, storage, VPC, Subnet, and appropriate Security Groups.
- Keep the remaining settings according to the instructions and select Restore DB instance to start the database restoration process.
- Monitor the creation status of the fcaj-2 DB Instance in the Amazon RDS interface and wait for the Restore process to complete.
- Verify that the new Database Instance appears in the Databases list and identify the separate DB Endpoint generated after restoration.
- Understand that restoring from a Snapshot creates an entirely new DB Instance with its own Endpoint; therefore, the application connection string must be updated when switching to the restored database.
- Learn how to verify connectivity and data integrity after restoration, and check Security Groups and related configurations to ensure appropriate access permissions.
- Review the completed Amazon RDS activities, including Database Instance creation, EC2 connectivity, Node.js application deployment, and database backup and restoration.
- Practice cleaning up the EC2 Instance by accessing EC2 Console → Instances, selecting ec2-instance, opening Instance state, and choosing Terminate (delete) instance according to the Workshop instructions.
- Access Amazon RDS, select the db-instance Database Instance, and use Modify to disable Enable deletion protection before deleting the database.
- Select Apply immediately to apply the change, then access Actions → Delete to remove the Database Instance.
- In the confirmation dialog, select I acknowledge that upon instance deletion, automated backups, including system snapshots and point-in-time recovery, will no longer be available; enter delete me and confirm Delete.
- Follow the same procedure to delete the fcaj-2 Database Instance after checking whether any data needs to be retained.
- Understand that deleting an RDS Database Instance may remove its automated backups and associated recovery capabilities; create a Final Snapshot before deletion when data retention is required.
- Wait for the Database Instance deletion process to complete before deleting the rds-subnet-group DB Subnet Group from the Amazon RDS Subnet groups section.
- Access Amazon VPC, open Internet gateways, select the rds-igw Internet Gateway, and choose Actions → Detach from VPC to detach the Internet Gateway from the VPC.
- Access Your VPCs, select the rds-vpc VPC, and choose Actions → Delete VPC according to the Workshop instructions.
- Inspect related resources after cleanup, particularly EBS Snapshots and CloudWatch Logs that may still exist if they have not been deleted separately.
